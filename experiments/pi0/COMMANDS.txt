Stop any existing policy, teleop mapper and original control engine before
switching to Pi0. joy_node alone may remain running.

With the scene reset and no object held, this starts the engine and waits for
fresh joints and Servo-stop acknowledgment before requesting OPEN. It waits

6. Run a physical Pi0 test — SAME COMMAND EACH ATTEMPT

Place the orange cube in the demonstrated workspace and keep the bowl/cameras
in their established positions. No object should be held at episode start.

bash "$PI0_ROOT/run.sh"

The wrapper checkpoints/pauses an active Pi0.5 training job and waits for its
workers to exit before checking GPU availability. Other GPU users are not
terminated. It then starts/prepares the Pi0 engine before checking gripper
observations, so a cold engine does not need a pre-existing gripper heartbeat.

Defaults: trained orange-cube instruction, explicit episode preparation, --speed-scale 0.5,
--actions-per-prediction 20. The first 20 of 50 predicted actions are issued at
10 Hz with five actions of prefetch; the engine smooths output at 125 Hz.
The fixed-bowl grasp-hold/release guard described above is active. After its
release confirmation, verify the actual placement and press Ctrl+C to finish.

Ctrl+C stops the policy and its model server. The engine's command watchdog
also stops output on disconnect. Use the pendant emergency stop for urgent
physical stopping. Wait for all old policy processes to exit before another run.

For the next trial: reset the scene, run standard_pose.sh if needed, and run
the same run.sh command. There is no attempt-number or recording-state gate.

Pi0 terminal logs: experiments/pi0/data/models/evaluation/pi0_tests/
Read-only check reports: experiments/pi0/data/models/evaluation/pi0_checks/
These are separate from earlier SmolVLA results. Terminal logs are not a full
per-attempt telemetry/video recorder or an automatic success score.
